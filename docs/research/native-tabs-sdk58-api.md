# Native tabs SDK 58 API evaluation

Checked 19 October 2026 for #528. Scope: installed `expo-router` 58.0.23 and `react-native-screens` 4.30.0. This is API/source evidence; simulator observations and the adopt/defer decision belong in the evaluation report. Web remains unchanged.

## Findings

SDK 58 exposes `NativeTabs` through `expo-router/native-tabs`. The older `unstable-native-tabs` import in historical examples is unnecessary. [SDK 58 reference](https://docs.expo.dev/versions/v58.0.0/sdk/router/native-tabs/)

**The API offers a guest Sign in action pattern.** Native `tabPress` is nonpreventable, so the current `event.preventDefault()` implementation cannot transfer directly. However, `disabled={guest}` suppresses native selection while still emitting `tabPress` with `data.isPrevented=true`; a listener can push `/login` without selecting Profile. Both platform views map `disabled` to `preventNativeSelection`. This is explicit installed implementation behavior, not proof of screen-reader activation or runtime reliability. Android opened login directly. The iOS first-tap failure was associated with a router-warning LogBox overlay; an unchanged listener passed 10/10 diagnostic trials with only those warnings suppressed. Resolve the underlying warnings before adoption; see the evaluation report. Disabled does not block JavaScript navigation or deep links; retain route/auth guards. Event and disabled contract (installed `expo-router/build/native-tabs/types.d.ts`), event implementation (installed `expo-router/build/native-tabs/NativeBottomTabsNavigator.js`)

**The existing Profile avatar cannot transfer as JSX.** Although `Icon.src` accepts a React element in its type, the converter only supports VectorIcon/PromiseIcon; arbitrary View/Image trees warn and return no icon. Image sources support separate default/selected variants and iOS `renderingMode="original"`. No icon crop, border radius, or focused-ring style API replaces the current circular View. A follow-up on iOS 27 confirmed that a remote `src` with `width: 28, height: 28, scale: 3` and `renderingMode="original"` renders correctly. The initial oversized image was a prototype defect, not a platform limitation. Prepared circular default/selected PNG variants and failed-image fallbacks were subsequently verified on both platforms. Android needed an unstable native override to avoid system tinting; this remains an integration cost. See [image research](native-tab-images-ios27.md). Converter (installed `expo-router/build/native-tabs/utils/icon.js`), icon contract (installed `expo-router/build/native-tabs/common/elements.d.ts`)

**Authentication changes tab structure.** Hidden triggers cannot be navigated to, and dynamic hiding resets state according to Expo. Installed code filters hidden triggers and keys the native view by visible route names. Inference: sign-in/sign-out needs explicit landing and state tests; hiding Home for guests is not equivalent to the existing bar-only `href: null`. Preserve guest `/` → Discover through the existing redirect, authenticated `/` → Home, and email/onboarding gates. [Visibility reference](https://docs.expo.dev/versions/v58.0.0/sdk/router/native-tabs/#hidden-1), wrapper (installed `expo-router/build/native-tabs/NativeBottomTabsNavigator.js`), [landing redirect](../../apps/mobile/src/app/(tabs)/index.tsx)

**Back and inset behavior need device checks.** Installed Android `backBehavior` defaults to `initialRoute`; `none` and `history` are alternatives. Existing details remain above tabs in the root Stack, whose anchor is `(tabs)`; changing the tab implementation does not itself require URL changes. Android automatically adds a bottom safe area; iOS automatically adjusts the first nested scroll view. Existing manual top/bottom padding may combine with this behavior. Test long content, keyboard, pull-to-refresh, detail Back, tab reselection, and login return before adoption. Back contract (installed `expo-router/build/native-tabs/types.d.ts`), [root Stack](../../apps/mobile/src/app/_layout.tsx), [inset reference](https://docs.expo.dev/versions/v58.0.0/sdk/router/native-tabs/#disableautomaticcontentinsets)

Accessibility labels are supported. Source inspection establishes available semantics, not VoiceOver/TalkBack correctness; the follow-up XCTest verified actual iOS 27 VoiceOver tab names, ordinal positions and selected state. Guest screen-reader activation, TalkBack speech, effective iOS enlarged text and contrast remain adoption checks. No code gates apply to this documentation-only note.
