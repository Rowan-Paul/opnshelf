# ADR 0030: Progressive, account-wide OAuth permissions

Opnshelf requests **Core Opnshelf Access** at sign-in through an evolving `xyz.opnshelf` permission set plus narrowly constrained image-blob access. Optional external ecosystems are excluded from that set and requested only when the User enables them: blog access after choosing a publication, and Bluesky posting when enabling a Cross-post. Each authorization atomically replaces one cumulative session containing Core Access, every previously enabled integration, and the new integration; a partial grant never replaces the working session.

External integration preferences are account-wide. A successful permission change revokes the superseded session and every other active device session, after warning that those devices must sign in again with the saved cumulative permission set. Declining optional access never blocks Core sign-in: it disables the declined integration account-wide while preserving its configuration for reconnection. Disconnecting performs the inverse reduced-scope authorization rather than merely hiding the feature locally.

We chose cumulative replacement over separate per-integration sessions so one authenticated request has one authoritative capability set, and chose account-wide consistency over per-device connections so saved publishing preferences cannot silently fail on another device. The costs are consent redirects for permission changes and forced re-login on other devices. Native-account credential sessions are signup bootstrap credentials only: after email verification they must be replaced by Core OAuth before onboarding continues. Existing broad OAuth sessions and verified credential sessions receive a one-time reset when this policy ships.
